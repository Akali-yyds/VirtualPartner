# 空间动作与等待思考姿态：实施记录

更新：2026-10-08。状态：实现中，尚未完成计划验收。

## 当前实现

保持 Momotalk → LlmRelay → StagePlan 2.0 → Validator → Player 主链路。新增 spatialPose 与 poseReset，原 bonePose 保留。未修改外部模型修复、TTS 或 ASR 服务。

- SpatialMotionData：空间轨迹协议及结构验证。手臂位置按头脚高度归一化；身体参考系在动作开始时固定，head/chest/shoulder 锚点随身体更新。
- SpatialPoseBuffer、SpatialMotionRuntime：离线 FK 预检、双骨链 IK、轨迹采样、双脚支撑、保持与恢复。最终写入仍通过 ActionCoordinator。
- TokiSpatialRig：当前角色方向、骨链长度、关节配置和等待思考轨迹。其他角色不能直接认为适配完成。
- 等待姿态由请求接受触发，首条呈现或请求结束释放；低于正式动作和 Debug 固定优先级。不是 LLM 的固定动作答案。
- PhoneLiveDebug 与构建器增加 Reset pose；运行时接口包含控制组复位。
- PerformanceLatency 分别记录提交、首 token、首完整 stage、播放调度、语音呈现、身体动作调度；10 月 8 日新增首次思考／空间骨骼写入。旧记录的 firstBodyDispatch 不能代表实际开始运动。

协议详见 `VirtualPartner/Assets/VirtualPartner/Prompts/spatial-motion.md`。

1. Unity JsonUtility 会为缺失的嵌套 completion 实例填入初始化默认值。原先该值为 idle，意外覆盖动作级 hold。现改为未指定时继承动作级设置；显式轨迹级 idle 仍优先。新增真实 JSON round-trip 断言。

3. 正式动作刚接受、尚未首次写入时，也禁止低优先级思考姿态替换其已预约控制组。
4. 新增末端朝向误差检查，以及局部复位保留无关保持、零时间首关键点的检查。

以上改动已通过 Unity 自带 Roslyn 独立编译：Runtime、Editor 均 exit 0。采用现有 Bee response 文件，输出到 Library/MCPForUnity/SpatialMotionReview/compile，没有覆盖编辑器程序集。警告为已有 PhoneAppHost 未使用字段和 PhonePagesReviewChecks 引用比较。
